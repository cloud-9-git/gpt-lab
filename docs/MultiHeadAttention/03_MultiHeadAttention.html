MultiHeadAttention 구현 학습

src/attention.py의 MultiHeadAttention을 구현하기 위한 문서입니다. 핵심은 Q/K/V를 만들고, head를 나누고, 미래 token을 못 보게 막은 뒤, 다시 하나의 벡터로 합치는 것입니다.

1. 목표 2. attention 의미 3. shape 기호 4. Q/K/V 5. head 나누기 6. score와 softmax 7. causal mask 8. head 합치기 9. 구현 순서 10. 테스트 기준 11. 자주 나는 실수

1. 목표

이 단계에서 구현하는 것은 GPT block 안에 들어가는 causal multi-head self-attention입니다. 말이 길지만 쪼개면 이렇게 보면 됩니다.

표현 뜻
self-attention 문장 안의 token들이 같은 문장 안의 다른 token들을 참고합니다.
causal GPT는 다음 token을 맞히는 모델이라 현재 위치에서 미래 token을 보면 안 됩니다.
multi-head embedding 차원을 여러 조각으로 나눠서 여러 attention을 동시에 계산합니다.
테스트가 요구하는 최소 결과는 두 가지입니다. 출력 shape는 입력과 같은 (batch_size, seq_len, d_model)이어야 하고, causal mask를 켜면 미래 위치의 attention weight가 0이어야 합니다.

2. attention 의미

Dataset 단계에서는 token ID가 embedding을 지나서 벡터가 됐습니다. attention은 각 위치의 벡터가 문장 안의 다른 위치 벡터를 얼마나 참고할지 정하는 계산입니다.

예를 들어 token이 4개 있으면, 각 token은 4개 token에 대한 점수를 갖습니다. 이 점수가 softmax를 지나면 비율이 됩니다. 

token 0이 참고하는 비율: [1.00, 0.00, 0.00, 0.00]
token 1이 참고하는 비율: [0.35, 0.65, 0.00, 0.00]
token 2이 참고하는 비율: [0.20, 0.30, 0.50, 0.00]
token 3이 참고하는 비율: [0.10, 0.20, 0.25, 0.45]

위 예시에서 오른쪽 위가 0인 이유가 causal mask입니다. 0번 token은 1, 2, 3번 token을 보면 안 됩니다. 1번 token은 2, 3번 token을 보면 안 됩니다.

3. shape 기호

이 구현은 shape만 놓치지 않으면 절반 이상 끝납니다. 앞으로 나오는 기호는 아래처럼 읽으면 됩니다.

기호 의미 예시
B batch size. 한 번에 처리하는 문장 조각 개수 2
T sequence length. 한 sample 안의 token 개수 10
C channel 또는 embedding 차원. 보통 d_model 64
H head 개수. n_heads 4
D head 하나가 맡는 차원. head_dim = d_model // n_heads 16 
x shape: (B, T, C)
예: batch_size=2, seq_len=10, d_model=64
x shape: (2, 10, 64)

4. Q/K/V

입력 x 하나에서 Q, K, V 세 종류의 벡터를 만듭니다. 모두 nn.Linear(d_model, d_model)을 통과해서 만듭니다.

이름 풀네임 역할
Q Query 현재 token이 무엇을 찾고 싶은지 나타내는 벡터
K Key 각 token이 어떤 특징을 갖고 있는지 비교용으로 내놓는 벡터
V Value attention 비율로 실제 섞일 정보 벡터

중요한 점은 Q, K, V 모두 처음 shape가 같습니다. 

q = self.q_proj(x)  # (B, T, C)
k = self.k_proj(x)  # (B, T, C)
v = self.v_proj(x)  # (B, T, C)

5. head 나누기

multi-head는 d_model 차원을 여러 조각으로 나누는 것입니다. 예를 들어 d_model=64, n_heads=4라면 head 하나는 16차원만 맡습니다. 

head_dim = d_model // n_heads
64 // 4 = 16

그래서 (B, T, C)를 (B, H, T, D)로 바꿉니다. PyTorch에서는 보통 view와 transpose를 같이 씁니다. 

q = q.view(B, T, self.n_heads, self.head_dim)
q = q.transpose(1, 2)

# (B, T, H, D) -> (B, H, T, D)
transpose(1, 2)는 1번 차원과 2번 차원을 바꾸라는 뜻입니다. (B, T, H, D)에서 T와 H 위치를 바꿔서 (B, H, T, D)를 만듭니다.

6. score와 softmax

attention score는 Q와 K를 곱해서 만듭니다. 각 token이 다른 token과 얼마나 관련 있는지를 점수로 계산하는 단계입니다. 

scores = q @ k.transpose(-2, -1)
scores = scores / (self.head_dim ** 0.5)

shape를 보면 왜 결과가 (B, H, T, T)인지 알 수 있습니다. 

q shape:              (B, H, T, D)
k.transpose shape:   (B, H, D, T)
scores shape:         (B, H, T, T)

마지막의 T, T는 "각 위치가 각 위치를 얼마나 볼지"를 뜻합니다. 예를 들어 T=4면 4 x 4 표가 만들어집니다. 

attn_weights = torch.softmax(scores, dim=-1)

dim=-1은 마지막 차원 기준으로 softmax를 하겠다는 뜻입니다. 한 token이 볼 수 있는 여러 위치들의 점수를 확률처럼 합이 1인 비율로 바꿉니다.

7. causal mask

GPT는 왼쪽에서 오른쪽으로 다음 token을 맞힙니다. 그래서 현재 위치에서 미래 위치를 보면 정답을 몰래 보는 셈이 됩니다. 이걸 막는 장치가 causal mask입니다.

T=4일 때 막아야 하는 위치는 아래처럼 오른쪽 위입니다. 

현재 위치 i가 미래 위치 j를 보면 안 됨: j > i

[
  [False, True,  True,  True ],
  [False, False, True,  True ],
  [False, False, False, True ],
  [False, False, False, False],
]

PyTorch에서는 이렇게 만들 수 있습니다. 

mask = torch.triu(
    torch.ones(T, T, dtype=torch.bool, device=x.device),
    diagonal=1,
)
scores = scores.masked_fill(mask, float("-inf"))

masked_fill은 mask가 True인 위치를 특정 값으로 바꿉니다. 미래 위치 score를 -inf로 만들면 softmax 뒤에는 0이 됩니다.

테스트는 return_attention_weights=True일 때 받은 attention weight에서 미래 위치 값이 0인지 직접 확인합니다. 그래서 mask는 softmax 전에 적용해야 합니다.

8. head 합치기

attention weight와 V를 곱하면 각 head별 결과가 나옵니다. 

context = attn_weights @ v

attn_weights shape: (B, H, T, T)
v shape:            (B, H, T, D)
context shape:      (B, H, T, D)

이제 head를 다시 합쳐서 원래 embedding 차원 C로 되돌립니다. 

context = context.transpose(1, 2)
context = context.contiguous().view(B, T, self.d_model)

# (B, H, T, D) -> (B, T, H, D) -> (B, T, C)

transpose를 하면 tensor의 메모리 배치가 이어져 있지 않을 수 있습니다. 그래서 view 전에 contiguous()를 붙이는 편이 안전합니다.

9. 구현 순서

1단계: __init__에서 layer 준비

self.q_proj = nn.Linear(d_model, d_model, bias=qkv_bias)
self.k_proj = nn.Linear(d_model, d_model, bias=qkv_bias)
self.v_proj = nn.Linear(d_model, d_model, bias=qkv_bias)
self.out_proj = nn.Linear(d_model, d_model)
self.dropout = nn.Dropout(drop_rate)

qkv_bias는 Q/K/V projection에 bias를 둘지 말지를 정하는 옵션입니다. 과제 템플릿이 인자로 받으므로 그대로 nn.Linear(..., bias=qkv_bias)에 넣으면 됩니다.

2단계: forward에서 B, T, C 꺼내기

B, T, C = x.shape

여기서 C는 d_model과 같아야 합니다.

3단계: Q/K/V 만들고 head 나누기

q = self.q_proj(x)
k = self.k_proj(x)
v = self.v_proj(x)

q = q.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
k = k.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
v = v.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)

4단계: attention score 계산

scores = q @ k.transpose(-2, -1)
scores = scores / (self.head_dim ** 0.5)

5단계: causal mask 적용

if causal_mask:
    mask = torch.triu(
        torch.ones(T, T, dtype=torch.bool, device=x.device),
        diagonal=1,
    )
    scores = scores.masked_fill(mask, float("-inf"))

6단계: softmax, dropout, V와 곱하기

attn_weights = torch.softmax(scores, dim=-1)
attn_weights = self.dropout(attn_weights)
context = attn_weights @ v

7단계: head를 합치고 output projection

context = context.transpose(1, 2).contiguous().view(B, T, self.d_model)
out = self.out_proj(context)

8단계: attention weight 반환 옵션 처리

if return_attention_weights:
    return out, attn_weights
return out
테스트에서 drop_rate=0.0으로 만들기 때문에 causal mask 검사가 안정적으로 됩니다. 학습할 때는 dropout이 attention weight 일부를 추가로 0으로 만들 수 있지만, 미래 위치가 0이어야 한다는 조건은 그대로 지켜져야 합니다.

11. 자주 나는 실수

1. mask를 softmax 뒤에 적용함

미래 위치를 0으로 만들려면 softmax 전에 score를 -inf로 바꿔야 합니다. softmax 뒤에 값을 억지로 0으로 바꾸면 한 줄의 합이 1이 아니게 됩니다.

2. k.transpose(-2, -1)를 빼먹음

q와 k는 둘 다 (B, H, T, D)입니다. score를 만들려면 마지막 두 차원을 (D, T)로 바꾼 key가 필요합니다.

3. head를 합칠 때 contiguous()를 빼먹음

transpose 뒤에는 view가 바로 실패할 수 있습니다. transpose(1, 2).contiguous().view(...) 순서로 쓰면 안전합니다.

4. mask tensor를 CPU에 만들어 GPU 입력과 섞음

입력 x가 GPU에 있는데 mask가 CPU에 있으면 device 오류가 납니다. torch.ones(..., device=x.device)처럼 입력과 같은 device에 만들어야 합니다.

5. d_model % n_heads 확인을 빼먹음

head를 똑같은 크기로 나눠야 하므로 d_model은 n_heads로 나누어떨어져야 합니다. 템플릿에 이미 이 검사가 들어있으니 유지하면 됩니다.
