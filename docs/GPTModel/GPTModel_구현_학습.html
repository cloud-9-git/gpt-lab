2. 복붙 전 이해해야 할 코드 읽는 법

아래 참고 코드는 과제 파일에 맞춘 버전이지만, 그냥 붙이면 다음 에러에서 다시 멈춥니다. 각 코드 블록을 볼 때는 항상 “모듈을 만든다”, “shape를 유지한다”, “반환 규칙을 맞춘다” 세 가지를 확인하세요.

__init__은 부품 등록

nn.Linear, LayerNorm, FeedForward처럼 학습할 parameter가 있는 부품은 __init__에서 self.xxx로 등록해야 optimizer가 찾습니다.

forward는 tensor 흐름

forward에서는 새 layer를 만들지 않고, 이미 등록한 layer에 입력 tensor를 통과시킵니다. 구현 중에는 각 줄 옆에 shape를 메모하면 좋습니다.

residual은 더하기 가능해야 함

x + something을 하려면 두 tensor shape가 같아야 합니다. 그래서 attention과 FFN은 둘 다 (B, T, C)를 반환해야 합니다.

loss는 class 차원이 마지막

cross_entropy는 (샘플 수, class 수) logits와 (샘플 수) target을 기대합니다. GPT에서는 모든 token 위치가 하나의 샘플입니다.

코드 패턴 읽는 방법
nn.Sequential(*[... for _ in range(n_layers)]) 같은 block을 config 개수만큼 쌓아서 순서대로 실행한다.
logits[:, -1, :] 생성에서 마지막 위치의 다음 token 점수만 사용한다.
view(-1, logits.size(-1)) batch와 sequence 차원을 합쳐 token 단위 classification 문제로 만든다.
torch.no_grad() 생성은 학습이 아니므로 gradient 기록을 끈다.

5. LayerNorm

LayerNorm은 각 token의 hidden vector 하나를 기준으로 평균과 분산을 계산합니다. 즉 (B, T, C) tensor에서 C 차원만 정규화합니다. batch 전체나 sequence 전체를 섞지 않기 때문에, 각 token 위치는 자기 hidden 값만 보고 안정화됩니다.

h1
h2
h3
h4
h5
h6
한 token의 hidden vector. 이 줄의 평균과 분산만 계산한다.

입력과 출력 shape는 그대로 (B, T, C)입니다. 값만 평균 0, 분산 1에 가깝게 바뀝니다.

역할 한 줄 요약

각 token의 hidden vector를 안정적인 범위로 맞춘 뒤 학습 가능한 scale/shift를 적용합니다.

입력/출력 shape

x: (B, T, C) -> out: (B, T, C)

필요한 PyTorch API

  • x.mean
  • x.var
  • torch.sqrt
  • nn.Parameter

구현 사고 순서

  1. x.mean(dim=-1, keepdim=True)로 마지막 차원의 평균을 구합니다.
  2. x.var(dim=-1, keepdim=True, unbiased=False)로 마지막 차원의 분산을 구합니다.
  3. (x - mean) / sqrt(var + eps)로 정규화합니다.
  4. 학습 가능한 gamma, beta를 적용합니다.
keepdim=True가 중요합니다. 그래야 (B, T, 1)이 되어 원래 (B, T, C)에 broadcast됩니다.
프로젝트 버전 참고 코드: LayerNorm.forward 
def forward(self, x: torch.Tensor) -> torch.Tensor:
    mean = x.mean(dim=-1, keepdim=True)
    var = x.var(dim=-1, keepdim=True, unbiased=False)
    norm_x = (x - mean) / torch.sqrt(var + self.eps)
    return self.gamma * norm_x + self.beta

흔한 에러

keepdim=False (B, T)가 되어 (B, T, C)와 broadcast가 어색해집니다.
dim=0 또는 dim=1 batch나 token 위치를 섞게 되어 LayerNorm 의도와 달라집니다.
unbiased=True 작은 hidden 차원에서 책/과제 기준 계산과 미묘하게 달라질 수 있습니다. 
pytest tests/test_model.py::TestLayerNorm::test_layernorm_shape -v
완료 체크: 입력과 같은 shape가 나오고, gamma/beta가 nn.Parameter로 남아 있으면 다음으로 이동합니다.

6. GELU와 FeedForward

FeedForward는 각 token 위치에 독립적으로 적용되는 작은 MLP입니다. attention이 token 사이의 정보를 섞는다면, FFN은 각 token의 hidden vector 내부 정보를 더 복잡하게 변환합니다.

입력
(B, T, C)
->
Linear
C -> 4C
->
GELU
->
Linear
4C -> C
->
Dropout

shape 변화: FFN 내부에서는 C가 잠깐 4C로 커지지만, block 밖으로 나올 때는 다시 (B, T, C)여야 residual connection을 할 수 있습니다.

역할 한 줄 요약

GELU는 부드러운 비선형성, FeedForward는 각 token hidden vector의 내부 변환입니다.

입력/출력 shape

GELU: any -> same, FFN: (B, T, C) -> (B, T, C)

필요한 PyTorch API

  • torch.tanh
  • torch.sqrt
  • torch.pow
  • nn.Linear
  • nn.Sequential
  • nn.Dropout

GELU

GELU는 ReLU처럼 음수 영역을 단순히 0으로 자르지 않고, 입력값 크기에 따라 부드럽게 통과 정도를 조절합니다. 과제에서는 tanh 근사식을 직접 구현해도 되고, PyTorch 연산으로 같은 식을 구성해도 됩니다. 

GELU(x) ~= 0.5 * x * (1 + tanh(sqrt(2 / pi) * (x + 0.044715 * x^3)))
프로젝트 버전 참고 코드: GELU.forward 
def forward(self, x: torch.Tensor) -> torch.Tensor:
    return 0.5 * x * (
        1 + torch.tanh(
            torch.sqrt(torch.tensor(2.0 / torch.pi, device=x.device, dtype=x.dtype))
            * (x + 0.044715 * torch.pow(x, 3))
        )
    )

FeedForward

이 과제의 FeedForward는 nn.Sequential로 만들면 가장 단순합니다. 입력 shape와 출력 shape는 모두 (B, T, d_model)이어야 합니다.

  • 첫 Linear: d_model에서 mult * d_model로 확장합니다.
  • 중간 활성화: 위에서 만든 GELU()를 사용합니다.
  • 두 번째 Linear: 다시 d_model로 줄입니다.
  • 마지막 Dropout: 학습 중 일부 값을 끄는 regularization입니다.
프로젝트 버전 참고 코드: FeedForward 
def __init__(self, d_model: int, dropout: float = 0.1, mult: int = 4):
    super().__init__()
    self.net = nn.Sequential(
        nn.Linear(d_model, mult * d_model),
        GELU(),
        nn.Linear(mult * d_model, d_model),
        nn.Dropout(dropout),
    )

def forward(self, x: torch.Tensor) -> torch.Tensor:
    return self.net(x)

흔한 에러

첫 Linear 출력이 d_model FFN의 확장 단계가 없어집니다. 첫 Linear는 mult * d_model로 가야 합니다.
두 번째 Linear도 mult * d_model 출력이 (B, T, 4C)가 되어 block residual에서 더할 수 없습니다.
GELU 상수를 CPU tensor로 고정 GPU에서 학습할 때 device mismatch가 날 수 있으니 x.device를 맞춥니다. 
pytest tests/test_model.py::TestGELU::test_gelu_shape -v
pytest tests/test_model.py::TestFeedForward::test_feedforward_shape -v
완료 체크: GELU는 어떤 입력 shape도 그대로 돌려주고, FFN은 hidden 차원을 확장했다가 정확히 d_model로 되돌립니다.

7. TransformerBlock

GPT block은 크게 두 번의 변환을 합니다. 먼저 normalized input을 causal self-attention에 넣고, 그 결과를 원래 입력에 더합니다. 그 다음 다시 normalized input을 FFN에 넣고, 또 원래 흐름에 더합니다. 이 과제 템플릿의 docstring처럼 Pre-LayerNorm 구조입니다.

x
LayerNorm 1
Causal Self-Attention
+
residual: x + attention(...)
LayerNorm 2
FeedForward
+
output: x + ffn(...)

shape 변화: 모든 단계가 (B, T, C)를 유지합니다. 이 불변식이 깨지면 residual 더하기가 바로 실패합니다.

역할 한 줄 요약

attention으로 token 사이 정보를 섞고, FFN으로 각 token 표현을 변환한 뒤 둘 다 residual로 보존합니다.

입력/출력 shape

x: (B, T, C) -> out: (B, T, C)

필요한 PyTorch/API

  • MultiHeadAttention
  • FeedForward
  • LayerNorm
  • tensor addition

구현 사고 순서

  1. self.att 또는 self.attention에 MultiHeadAttention을 둡니다.
  2. self.ffn에 FeedForward를 둡니다.
  3. self.norm1, self.norm2를 각각 만듭니다.
  4. forward에서 x = x + attention(norm1(x)) 흐름을 만듭니다.
  5. 그 다음 x = x + ffn(norm2(x)) 흐름을 만듭니다.
drop_rate는 이미 MultiHeadAttention과 FeedForward 안으로 전달됩니다. 별도 dropout layer를 더 둘 수도 있지만, 이 과제 테스트에는 shape 유지가 핵심입니다.
프로젝트 버전 참고 코드: TransformerBlock 
def __init__(
    self,
    d_model: int,
    n_heads: int,
    drop_rate: float = 0.1,
    qkv_bias: bool = False,
):
    super().__init__()
    self.att = MultiHeadAttention(
        d_model=d_model,
        n_heads=n_heads,
        drop_rate=drop_rate,
        qkv_bias=qkv_bias,
    )
    self.ffn = FeedForward(d_model, dropout=drop_rate)
    self.norm1 = LayerNorm(d_model)
    self.norm2 = LayerNorm(d_model)

def forward(self, x: torch.Tensor, causal_mask: bool = True) -> torch.Tensor:
    shortcut = x
    x = self.norm1(x)
    x = self.att(x, causal_mask=causal_mask)
    x = shortcut + x

    shortcut = x
    x = self.norm2(x)
    x = self.ffn(x)
    x = shortcut + x
    return x

흔한 에러

shortcut을 한 번만 저장 두 번째 residual은 attention을 지난 값을 기준으로 새로 저장해야 합니다.
LayerNorm을 attention/FFN 뒤에 적용 이 템플릿은 Pre-LN입니다. 먼저 normalize한 뒤 sublayer에 넣습니다.
causal_mask 인자를 attention에 전달하지 않음 테스트와 생성에서 미래 token을 보는지 여부를 제어하기 어렵습니다. 
pytest tests/test_model.py::TestTransformerBlock::test_transformer_block_shape -v
완료 체크: block 입력과 출력 shape가 같고, attention residual과 FFN residual이 각각 따로 있습니다.

8. GPTModel

GPTModel은 지금까지 만든 부품을 순서대로 연결합니다. 입력은 token ID인 idx이고, 출력은 각 위치마다 vocabulary 전체에 대한 점수인 logits입니다.

idx
(B, T)
->
self.embedding
->
self.blocks
->
self.final_norm
->
self.lm_head

shape 변화: idx (B, T) -> embedding/block/final norm (B, T, emb_dim) -> LM head (B, T, vocab_size).

역할 한 줄 요약

embedding부터 LM head까지 연결해서 다음 token 예측 logits와 선택적으로 loss를 반환합니다.

입력/출력 shape

idx: (B, T) -> logits: (B, T, V), target이 있으면 scalar loss도 반환합니다.

필요한 PyTorch/API

  • InputEmbedding
  • nn.Sequential
  • nn.Linear
  • torch.nn.functional.cross_entropy
  • Tensor.view

__init__에서 만들 것

모듈 역할 config key
InputEmbedding token ID를 (B, T, emb_dim)으로 바꿈 vocab_size, emb_dim, context_length, drop_rate
nn.Sequential blocks TransformerBlock을 n_layers개 쌓음 n_layers, n_heads, qkv_bias
LayerNorm 마지막 출력 hidden state를 안정화 emb_dim
nn.Linear LM head hidden vector를 vocabulary 점수로 바꿈 emb_dim, vocab_size

forward에서 할 일

  1. idx를 embedding에 넣어 x를 만듭니다.
  2. x를 block stack에 통과시킵니다.
  3. final LayerNorm을 적용합니다.
  4. LM head로 logits를 만듭니다.
  5. targets is None이면 logits만 반환합니다.
  6. targets가 있으면 token 단위 cross entropy loss와 logits를 함께 반환합니다.
Cross entropy는 마지막 차원이 class 수여야 합니다. 그래서 logits는 (B*T, V), targets는 (B*T)로 flatten해서 계산합니다.

반환 경로 비교

idx
->
logits 생성
->
targets 없음
return logits
또는
targets 있음
return loss, logits

테스트는 두 경로를 모두 봅니다. targets=None일 때 tuple을 강제로 반환하지 않는 편이 가장 단순합니다.

loss flatten 흐름

logits
(B, T, V)
->
view(-1, V)
=
(B*T, V)
targets
(B, T)
->
view(-1)
=
(B*T)

vocabulary의 각 token ID가 class입니다. 그래서 class 수는 V이고, 모든 위치 B*T개가 학습 샘플입니다.

프로젝트 버전 참고 코드: GPTModel 
def __init__(self, config: dict):
    super().__init__()
    self.config = config
    self.embedding = InputEmbedding(
        vocab_size=config["vocab_size"],
        emb_dim=config["emb_dim"],
        context_length=config["context_length"],
        drop_rate=config["drop_rate"],
    )
    self.blocks = nn.Sequential(
        *[
            TransformerBlock(
                d_model=config["emb_dim"],
                n_heads=config["n_heads"],
                drop_rate=config["drop_rate"],
                qkv_bias=config["qkv_bias"],
            )
            for _ in range(config["n_layers"])
        ]
    )
    self.final_norm = LayerNorm(config["emb_dim"])
    self.lm_head = nn.Linear(config["emb_dim"], config["vocab_size"], bias=False)

def forward(
    self,
    idx: torch.Tensor,
    targets: torch.Tensor | None = None,
) -> torch.Tensor | tuple[torch.Tensor, torch.Tensor]:
    x = self.embedding(idx)
    x = self.blocks(x)
    x = self.final_norm(x)
    logits = self.lm_head(x)

    if targets is None:
        return logits

    loss = torch.nn.functional.cross_entropy(
        logits.view(-1, logits.size(-1)),
        targets.view(-1),
    )
    return loss, logits

흔한 에러

LM head 입력 차원을 context_length로 둠 LM head는 각 hidden vector를 vocab 점수로 바꾸므로 입력 차원은 emb_dim입니다.
LM head 출력 차원을 emb_dim으로 둠 다음 token을 고르려면 vocabulary 전체 점수가 필요하므로 출력은 vocab_size입니다.
loss 계산에서 flatten하지 않음 cross_entropy 입력 shape 요구와 맞지 않아 에러가 납니다.
self.config를 저장하지 않음 뒤 단계인 fine-tuning 코드가 gpt_model.config["emb_dim"]을 참조할 수 있습니다. 
pytest tests/test_model.py::TestGPTModel::test_gpt_forward_shape -v
pytest tests/test_model.py::TestGPTModel::test_gpt_forward_with_targets_returns_loss -v
완료 체크: model(idx)는 logits만, model(idx, targets)는 scalar loss와 logits를 반환합니다.

9. generate_text_simple

생성은 이미 있는 token 뒤에 새 token을 하나씩 붙이는 반복입니다. 현재 context가 너무 길면 모델의 최대 문맥 길이인 context_size만큼 뒤에서 잘라 사용합니다. simple 버전은 sampling 없이 가장 점수가 큰 token을 고르는 greedy 방식입니다.

shape 변화: 모델 입력은 매번 idx_cond: (B, <= context_size)이고, 새 token idx_next: (B, 1)을 기존 idx 뒤에 붙입니다.

역할 한 줄 요약

현재 token sequence에서 다음 token을 greedy로 하나씩 골라 뒤에 붙입니다.

입력/출력 shape

idx: (B, start_len) -> out: (B, start_len + max_new_tokens)

필요한 PyTorch API

  • torch.no_grad
  • torch.argmax
  • torch.cat
  • tensor slicing

이 과정을 max_new_tokens번 반복합니다. 테스트 예시는 시작 길이 4, 새 token 6개라 최종 길이 10입니다.

구현 사고 순서

  1. max_new_tokens번 반복합니다.
  2. idx[:, -context_size:]로 현재 모델 입력을 자릅니다.
  3. torch.no_grad() 안에서 모델을 호출합니다.
  4. logits[:, -1, :]로 마지막 위치의 다음 token 점수만 가져옵니다.
  5. torch.argmax(..., dim=-1, keepdim=True)로 다음 token ID를 고릅니다.
  6. torch.cat((idx, idx_next), dim=1)로 결과를 이어 붙입니다.
프로젝트 버전 참고 코드: generate_text_simple 
def generate_text_simple(
    model: GPTModel,
    idx: torch.Tensor,
    max_new_tokens: int,
    context_size: int,
) -> torch.Tensor:
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -context_size:]
        with torch.no_grad():
            logits = model(idx_cond)
        logits = logits[:, -1, :]
        idx_next = torch.argmax(logits, dim=-1, keepdim=True)
        idx = torch.cat((idx, idx_next), dim=1)
    return idx

흔한 에러

keepdim=False idx_next가 (B)가 되어 idx (B, T)와 concat하기 어렵습니다.
dim=0 concat batch 방향으로 붙어서 sequence 길이가 늘지 않습니다. token은 dim=1로 붙입니다.
전체 logits에 argmax 마지막 위치 logits[:, -1, :]만 다음 token 후보입니다.
context를 자르지 않음 생성 중 sequence가 context_length보다 길어져 position embedding 범위를 넘을 수 있습니다.

완료 체크: 반복 1번마다 sequence 길이가 정확히 1씩 늘고, 최종 길이는 start_len + max_new_tokens입니다.
