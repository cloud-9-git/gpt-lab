# mini GPT 실험 가설 추천 후보

이 문서는 `REPORT.md`에 넣을 실험 가설을 고르기 위한 후보 모음이다.  
가설은 “실제로 비교할 수 있는 조건”과 “판단할 지표”가 있어야 한다.

## 1. 추천 메인 가설

### 가설 A. 사전 학습 checkpoint는 감성 분류 성능을 높일 것이다

**가설**

NSMC 리뷰 텍스트로 사전 학습한 GPT backbone을 사용하면, 랜덤 초기화 GPT backbone보다 감성 분류 미세 조정에서 더 낮은 validation loss와 더 높은 accuracy를 보일 것이다.

**이유**

사전 학습 과정에서 모델은 NSMC 리뷰의 토큰 패턴, 자주 등장하는 표현, 긍정/부정 리뷰 말투를 일부 학습한다. 따라서 같은 구조의 랜덤 모델보다 감성 분류에 필요한 표현을 더 빨리 학습할 가능성이 있다.

**비교 조건**

| 실험군 | backbone 초기화 | classifier |
| --- | --- | --- |
| A-1 | 랜덤 초기화 GPTModel | 새로 초기화 |
| A-2 | `checkpoint_step_3500.pt` 로드 GPTModel | 새로 초기화 |

**고정할 조건**

- tokenizer: `data/tokenizer_vocab3000.json`
- vocab_size: 3000
- context_length: 128
- emb_dim: 128
- n_heads: 4
- n_layers: 2
- train/val/test split: 동일하게 유지
- fine-tuning epoch, batch_size, learning_rate: 동일하게 유지

**판단 지표**

- validation loss
- validation accuracy
- test loss
- test accuracy

**REPORT에 쓰기 좋은 결론 형태**

```text
사전 학습 checkpoint를 사용한 모델은 랜덤 초기화 모델보다 validation/test accuracy가 높았다.
이는 사전 학습이 NSMC 리뷰의 언어적 패턴을 backbone에 미리 학습시켜 감성 분류 미세 조정에 도움이 되었기 때문으로 해석할 수 있다.
```

또는 결과가 좋지 않을 경우:

```text
사전 학습 checkpoint를 사용했지만 랜덤 초기화 모델보다 뚜렷한 성능 향상은 관찰되지 않았다.
이는 사전 학습 모델 규모가 작고, 사전 학습 loss가 아직 높은 상태였기 때문으로 판단된다.
```

## 2. 사전 학습 관련 가설 후보

### 가설 B. vocab 3000 BPE는 vocab 260 byte tokenizer보다 한국어 생성 품질을 높일 것이다

**가설**

vocab 3000 BPE tokenizer를 사용하면 vocab 260 byte tokenizer보다 token 수가 줄고, 생성 문장 내 깨진 문자와 byte 조합 오류가 감소할 것이다.

**이유**

vocab 260은 특수 토큰 4개와 byte 256개만 포함한다. 한글 한 글자는 UTF-8 byte 여러 개로 표현되므로 모델이 byte 조합을 잘못 생성하면 `�`가 쉽게 생긴다. BPE merge를 사용하면 자주 등장하는 byte 조합과 부분 문자열이 더 큰 token으로 묶여 생성 안정성이 좋아질 수 있다.

**비교 조건**

| 실험군 | tokenizer | vocab_size |
| --- | --- | ---: |
| B-1 | byte tokenizer | 260 |
| B-2 | BPE tokenizer | 3000 |

**판단 지표**

- train token 수
- validation loss
- 생성 샘플 내 `�` 개수
- 사람이 읽었을 때 리뷰 표현이 얼마나 자연스러운지

**현재 관찰값**

| 항목 | vocab 260 | vocab 3000 |
| --- | ---: | ---: |
| train token 수 | 3,335,336 | 805,112 |
| validation token 수 | 291,753 | 69,868 |

### 가설 C. 사전 학습 epoch를 늘리면 validation loss가 더 감소할 것이다

**가설**

현재 Basic 설정에서 epoch를 5에서 10으로 늘리면 validation loss가 추가로 감소할 것이다.

**이유**

현재 vocab 3000 사전 학습 결과에서 train loss와 validation loss가 함께 감소하고 있으며, 마지막 step까지 validation loss 상승이 관찰되지 않았다. 따라서 아직 과적합보다는 과소학습 상태일 가능성이 높다.

**현재 결과**

| step | train loss | val loss |
| ---: | ---: | ---: |
| 100 | 7.3339 | 7.3460 |
| 1500 | 6.7248 | 6.7926 |
| 3100 | 5.8745 | 5.9730 |
| 3930 | 5.6334 | 5.8143 |

**판단 지표**

- validation loss가 계속 감소하는지
- train loss만 감소하고 validation loss가 증가하는 과적합이 발생하는지
- 생성 샘플의 문장성이 개선되는지

### 가설 D. context_length 128은 context_length 64보다 긴 리뷰 패턴을 더 잘 학습할 것이다

**가설**

context_length를 64에서 128로 늘리면 모델이 더 긴 문맥을 참고할 수 있어 validation loss와 생성 품질이 개선될 것이다.

**이유**

GPT는 입력 context 안에서만 이전 token을 참고한다. context_length가 길수록 긴 리뷰의 앞뒤 관계를 더 많이 볼 수 있다.

**비교 조건**

| 실험군 | context_length |
| --- | ---: |
| D-1 | 64 |
| D-2 | 128 |

**주의점**

context_length가 길어지면 같은 token 수에서 batch 수가 줄고, attention 계산량은 증가한다. 따라서 학습 시간이 늘 수 있다.

**판단 지표**

- validation loss
- 생성 샘플의 문맥 유지 정도
- 학습 시간

**실행 명령**

D-1: `context_length=64`

```bash
MPLCONFIGDIR=.cache/matplotlib python scripts/pretrain_local.py \
  --vocab-size 3000 \
  --context-length 64 \
  --emb-dim 128 \
  --n-heads 4 \
  --n-layers 2 \
  --batch-size 8 \
  --epochs 5 \
  --eval-freq 100 \
  --eval-iter 5 \
  --ckpt-freq 500 \
  --tokenizer-train-chars 1500000 \
  --train-chars 1500000 \
  --val-chars 120000 \
  --tokenizer-path data/tokenizer_vocab3000.json \
  --train-token-cache data/train_token_ids_vocab3000.pt \
  --val-token-cache data/val_token_ids_vocab3000.pt \
  --ckpt-dir checkpoints/context64 \
  --final-ckpt-path checkpoints/context64/pretrain_final.pt \
  --results-path outputs/pretrain_context64_results.json \
  --loss-plot-path outputs/pretrain_context64_loss.png \
  | tee pretrain_context64_vocab3000.log
```

### 가설 E. 모델 크기를 키우면 validation loss가 낮아질 것이다

**가설**

`emb_dim`과 `n_layers`를 키우면 더 복잡한 리뷰 패턴을 표현할 수 있어 validation loss가 감소할 것이다.

**비교 조건**

| 실험군 | emb_dim | n_layers | n_heads |
| --- | ---: | ---: | ---: |
| E-1 | 128 | 2 | 4 |
| E-2 | 192 | 4 | 4 |

**주의점**

모델이 커지면 학습 시간과 메모리 사용량이 증가한다. 데이터가 작으면 train loss만 낮아지고 validation loss는 좋아지지 않는 과적합이 생길 수 있다.

**판단 지표**

- validation loss
- train/validation loss 간격
- 학습 시간
- 생성 샘플 품질

## 3. 감성 분류 미세 조정 관련 가설 후보

### 가설 F. 마지막 non-pad token hidden state는 마지막 위치 hidden state보다 분류 성능이 좋을 것이다

**가설**

감성 분류에서 `x[:, -1, :]`를 사용하는 대신 padding이 아닌 마지막 유효 token의 hidden state를 사용하면 validation accuracy가 향상될 것이다.

**이유**

분류 데이터는 padding으로 길이를 맞춘다. 리뷰가 `max_length`보다 짧으면 마지막 위치는 실제 리뷰 token이 아니라 `<pad>`일 수 있다. 이 경우 `x[:, -1, :]`는 문장 끝 표현이 아니라 padding 위치 표현이다.

**비교 조건**

| 실험군 | pooling 방식 |
| --- | --- |
| F-1 | `x[:, -1, :]` |
| F-2 | 마지막 non-pad token hidden state |

**판단 지표**

- validation accuracy
- test accuracy
- validation loss

### 가설 G. classifier만 학습하는 것보다 backbone 일부를 함께 학습하는 것이 성능이 좋을 것이다

**가설**

classifier head만 학습하는 것보다 마지막 TransformerBlock과 final LayerNorm을 함께 학습하면 감성 분류 accuracy가 높아질 것이다.

**이유**

classifier만 학습하면 GPT backbone의 표현은 고정된다. 마지막 block까지 함께 미세 조정하면 감성 분류에 더 적합한 표현으로 일부 조정할 수 있다.

**비교 조건**

| 실험군 | 학습 대상 |
| --- | --- |
| G-1 | classifier만 |
| G-2 | classifier + final_norm + 마지막 TransformerBlock |
| G-3 | 전체 backbone + classifier |

**판단 지표**

- validation accuracy
- test accuracy
- train/validation loss 간격
- 학습 시간

### 가설 H. backbone과 classifier의 learning rate를 분리하면 미세 조정이 안정적일 것이다

**가설**

사전 학습된 backbone에는 작은 learning rate를, 새로 붙인 classifier에는 큰 learning rate를 적용하면 validation accuracy가 향상될 것이다.

**이유**

backbone은 이미 학습된 표현을 가지고 있으므로 너무 큰 learning rate로 업데이트하면 사전 학습 표현이 손상될 수 있다. 반면 classifier는 랜덤 초기화 상태이므로 더 빠르게 학습할 필요가 있다.

**비교 조건**

| 실험군 | backbone lr | classifier lr |
| --- | ---: | ---: |
| H-1 | 3e-4 | 3e-4 |
| H-2 | 1e-5 | 3e-4 |
| H-3 | 5e-5 | 5e-4 |

**판단 지표**

- validation loss
- validation accuracy
- 학습 안정성

## 4. 우선순위 추천

시간이 제한되어 있다면 아래 순서로 진행한다.

1. **가설 A**: 랜덤 초기화 vs 사전 학습 checkpoint 감성 분류 비교
2. **가설 F**: 마지막 token vs 마지막 non-pad token 비교
3. **가설 C**: 사전 학습 epoch 추가
4. **가설 G**: classifier만 학습 vs 일부 backbone 학습
5. **가설 D/E**: context_length 또는 모델 크기 비교

제출 보고서의 중심 가설은 가설 A가 가장 적합하다. 이 과제의 흐름이 “사전 학습한 mini GPT를 감성 분류에 미세 조정한다”는 구조이기 때문이다.

## 5. REPORT에 바로 넣기 좋은 최종 가설 문장

```text
본 실험의 주요 가설은 NSMC 리뷰 텍스트로 사전 학습한 GPT backbone이 랜덤 초기화된 GPT backbone보다 감성 분류 미세 조정에서 더 좋은 성능을 낼 것이라는 점이다. 사전 학습 과정에서 모델이 리뷰 도메인의 토큰 패턴과 자주 등장하는 감성 표현을 미리 학습하므로, 동일한 분류 head를 붙였을 때 validation/test accuracy가 높아지고 loss가 낮아질 것으로 예상했다.
```
