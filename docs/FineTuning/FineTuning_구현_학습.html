막혔을 때 바로 보는 표

`finetune.py`는 언어 모델을 새로 만드는 파일이 아니라, 이미 만든 GPT backbone 위에 감성 분류용 데이터 파이프라인과 head를 붙이는 파일입니다. 아래 표에서 지금 막힌 증상을 찾아 해당 섹션으로 이동하세요.

지금 막힌 곳 봐야 할 섹션 핵심 한 줄
NSMC TSV에서 빈 리뷰 제거, train/val/test 분리 make_sentiment_dataset `document`가 비어 있으면 버리고 `{"text": 리뷰, "label": int}` 형태로 바꿉니다.
`Dataset.__getitem__`에서 padding/truncation이 헷갈림 ReviewSentimentDataset encode 결과를 `max_length`로 자르고, 부족하면 `pad_id`를 뒤에 붙입니다.
분류 logits shape가 `(B, 2)`가 안 나옴 GPTForSequenceClassification GPT의 마지막 token hidden state `(B, C)`에 `nn.Linear(C, num_labels)`를 적용합니다.
GPTModel이 logits만 반환해서 hidden state를 못 꺼냄 hidden state 꺼내기 `self.gpt(input_ids)` 대신 `embedding -> blocks -> final_norm`을 직접 통과시킵니다.
`cross_entropy`에서 dtype 에러 발생 loss 명세 분류 label은 one-hot이 아니라 class index이고 dtype은 반드시 `torch.long`입니다.
훈련은 되는데 accuracy 계산이 이상함 accuracy 명세 `logits.argmax(dim=-1)`과 `labels`를 비교하고, 맞은 개수를 전체 샘플 수로 나눕니다.
eval에서 메모리가 커지거나 dropout이 계속 동작함 train/eval mode 평가는 `model.eval()`과 `with torch.no_grad():`를 함께 씁니다.
이 문서는 공부용 참고 코드와 구현 명세를 제공합니다. 실제 과제 파일인 `src/finetune.py`는 여기서 수정하지 않았고, 이 HTML도 `docs/index.html`에 연결하지 않는 독립 문서입니다.

PyTorch 함수와 구현 명세

이 섹션은 구현 중 계속 돌아와 보는 API 사전입니다. 각 함수가 받는 shape, 반환 shape, dtype을 함께 확인하세요.

Dataset과 Tensor

API 무엇을 하는가 이 과제에서의 사용법
torch.utils.data.Dataset index로 샘플 하나를 꺼낼 수 있는 추상 class `__len__`은 샘플 수, `__getitem__`은 `(input_ids, label)` 하나를 반환합니다.
torch.tensor(data, dtype=torch.long) Python list를 tensor로 변환 token id와 class label은 index 값이므로 `torch.long`이 안전합니다.
tensor.to(device) tensor를 CPU/GPU device로 이동 훈련 loop 안에서 `input_ids`와 `labels`를 둘 다 같은 device로 옮깁니다.
tensor.long() dtype을 `torch.int64`로 변환 `cross_entropy` target label은 반드시 long dtype이어야 합니다.

Model과 Head

API 입력 출력/주의점
nn.Module 모델 class의 부모 `super().__init__()`을 먼저 호출해야 submodule이 등록됩니다.
nn.Dropout(p) 아무 shape tensor train mode에서는 일부 값을 0으로 만들고, eval mode에서는 사실상 통과시킵니다.
nn.Linear(in_features, out_features) 마지막 차원이 `in_features`인 tensor `(B,C)`를 넣으면 `(B,out_features)`가 됩니다. 분류 head는 `nn.Linear(emb_dim, num_labels)`입니다.
nn.ModuleList module 목록 저장 직접 호출하지 말고 `for block in self.gpt.blocks: x = block(x)`처럼 순회합니다.

Loss와 Optimizer

API 정확한 계약 흔한 실수
torch.nn.functional.cross_entropy(logits, labels) `logits.shape == (B, num_labels)`, `labels.shape == (B,)`, `labels.dtype == torch.long` labels를 one-hot `(B,2)`로 만들면 안 됩니다. class index `0` 또는 `1`이어야 합니다.
optimizer.zero_grad() 이전 step의 gradient 누적값 제거 빼먹으면 gradient가 batch마다 계속 누적됩니다.
loss.backward() loss에서 모든 parameter gradient 계산 `torch.no_grad()` 안에서 호출하면 gradient가 없습니다.
optimizer.step() 계산된 gradient로 parameter 업데이트 `backward()` 전에 호출하면 업데이트할 gradient가 없습니다.

Accuracy

preds = logits.argmax(dim=-1)          # (B,)
correct = (preds == labels).sum().item()
total = labels.size(0)
accuracy = correct / total

`argmax(dim=-1)`은 각 샘플에서 가장 점수가 높은 class index를 뽑습니다. logits가 `(B,2)`이면 결과는 `(B,)`입니다.

Train/Eval Mode

train loop
->
model.train()
->
backward
->
optimizer.step()

훈련에서는 dropout이 켜지고 gradient가 필요합니다.

eval loop
->
model.eval()
->
torch.no_grad()
->
loss/accuracy

평가에서는 dropout이 꺼지고 gradient graph를 만들지 않습니다.

make_sentiment_dataset

역할: TSV -> list[dict] 입력: NSMC ratings_train/test 출력: train, val, test

NSMC 파일은 보통 `id`, `document`, `label` 컬럼을 가진 TSV입니다. `document`가 빈 문자열인 행은 학습에 쓸 수 없으므로 버리고, 나머지는 `{"text": document, "label": int(label)}` 형태로 바꿉니다.

입력/출력 shape가 아니라 구조

이름 구조 예시
`train_tsv_path` 파일 경로 `ratings_train.txt`
반환 `train_data` `list[dict]` `[{"text": "정말 좋았다", "label": 1}, ...]`
반환 `val_data` `list[dict]` train TSV에서 seed 기반 shuffle 후 일부 분리
반환 `test_data` `list[dict]` `test_tsv_path`가 없으면 빈 list

구현 순서

  1. `csv.DictReader(..., delimiter="\t")`로 TSV를 읽습니다.
  2. `document`를 가져와 `strip()`한 뒤 빈 문자열이면 건너뜁니다.
  3. `label`을 `int`로 바꿔 `{"text": text, "label": label}` dict를 만듭니다.
  4. `random.Random(seed).shuffle(train_rows)`로 재현 가능한 shuffle을 합니다.
  5. `val_ratio`만큼 validation을 앞에서 떼고 나머지를 train으로 둡니다.
  6. `output_dir`가 있으면 JSONL 같은 사람이 읽기 쉬운 파일로 저장해도 됩니다.
테스트가 실제로 확인하는 것: 빈 리뷰 하나가 제거되어 train+val 합이 3이고, test는 1개이며, 각 항목 key가 `text`, `label`인지 봅니다.
프로젝트 버전 참고 코드: make_sentiment_dataset 
def make_sentiment_dataset(
    train_tsv_path: str | Path,
    test_tsv_path: str | Path | None = None,
    val_ratio: float = 0.08,
    seed: int = 42,
    output_dir: str | Path | None = None,
) -> tuple[list[dict], list[dict], list[dict]]:
    import csv
    import json
    import random

    def read_nsmc_tsv(path: str | Path) -> list[dict]:
        rows = []
        with Path(path).open("r", encoding="utf-8") as f:
            reader = csv.DictReader(f, delimiter="\t")
            for row in reader:
                text = (row.get("document") or "").strip()
                if not text:
                    continue
                rows.append({"text": text, "label": int(row["label"])})
        return rows

    train_rows = read_nsmc_tsv(train_tsv_path)
    rng = random.Random(seed)
    rng.shuffle(train_rows)

    if len(train_rows) <= 1 or val_ratio <= 0:
        val_size = 0
    else:
        val_size = int(len(train_rows) * val_ratio)
        if val_ratio > 0:
            val_size = max(1, val_size)
        val_size = min(val_size, len(train_rows) - 1)

    val_data = train_rows[:val_size]
    train_data = train_rows[val_size:]
    test_data = read_nsmc_tsv(test_tsv_path) if test_tsv_path is not None else []

    if output_dir is not None:
        output_path = Path(output_dir)
        output_path.mkdir(parents=True, exist_ok=True)

        def write_jsonl(name: str, data: list[dict]) -> None:
            lines = [json.dumps(item, ensure_ascii=False) for item in data]
            Path(output_path, name).write_text("\n".join(lines), encoding="utf-8")

        write_jsonl("sentiment_train.jsonl", train_data)
        write_jsonl("sentiment_val.jsonl", val_data)
        write_jsonl("sentiment_test.jsonl", test_data)

    return train_data, val_data, test_data

흔한 에러와 원인

증상 원인 해결
`KeyError: 'document'` TSV header를 일반 split으로 잘못 읽었거나 delimiter가 틀림 `csv.DictReader(f, delimiter="\t")`를 씁니다.
빈 리뷰가 남아 있음 `text == ""`만 검사하고 공백 문자열을 놓침 `strip()` 후 `if not text:`로 검사합니다.
매번 val split이 달라짐 전역 `random.shuffle`을 seed 없이 사용 `random.Random(seed)` 인스턴스를 만듭니다.
완료 체크

ReviewSentimentDataset

역할: 리뷰 1개 -> tensor 1개 입력: dict index 출력: `(input_ids, label)`

`DataLoader`는 샘플마다 길이가 다른 list를 batch tensor로 자동 변환하지 못합니다. 그래서 `__getitem__`에서 모든 리뷰를 같은 길이 `max_length`로 맞춰야 합니다.

"재미있다"
->
tokenizer.encode
->
[2, 31, 12, 3]
->
pad/truncate
->
(max_length,)

샘플 하나의 shape는 `(T,)`입니다. DataLoader가 batch로 묶으면 `(B,T)`가 됩니다.

정확한 반환 계약

반환값 타입 shape/value
`input_ids` `torch.Tensor` shape `(max_length,)`, dtype `torch.long`
`label` `int` 또는 long tensor로 collate 가능한 값 `0` 또는 `1`

구현 순서

  1. `item = self.data[idx]`로 dict 하나를 꺼냅니다.
  2. `self.tokenizer.encode(item["text"], add_bos_eos=True)`로 token id list를 만듭니다.
  3. `ids = ids[:self.max_length]`로 너무 긴 리뷰를 자릅니다.
  4. `ids += [self.pad_id] * (self.max_length - len(ids))`로 부족한 길이를 채웁니다.
  5. `torch.tensor(ids, dtype=torch.long)`로 변환합니다.
  6. `int(item["label"])`을 함께 반환합니다.
프로젝트 버전 참고 코드: ReviewSentimentDataset.__getitem__ 
def __getitem__(self, idx: int) -> tuple[torch.Tensor, int]:
    item = self.data[idx]
    ids = self.tokenizer.encode(item["text"], add_bos_eos=True)

    ids = ids[: self.max_length]
    pad_len = self.max_length - len(ids)
    if pad_len > 0:
        ids = ids + [self.pad_id] * pad_len

    input_ids = torch.tensor(ids, dtype=torch.long)
    label = int(item["label"])
    return input_ids, label

PyTorch 명세

함수 왜 쓰는가 주의점
torch.tensor(ids, dtype=torch.long) Python list를 모델 입력 tensor로 바꿈 `torch.long`이 아니면 embedding index나 loss target에서 문제가 날 수 있습니다.
DataLoader(dataset, batch_size=...) `__getitem__` 결과 여러 개를 batch로 쌓음 샘플 길이가 모두 같아야 `(B,T)` tensor로 잘 쌓입니다.

흔한 에러와 원인

증상 원인 해결
`input_ids.shape`가 `(4,)`처럼 제각각 padding을 하지 않음 항상 `max_length`까지 뒤에 pad token을 붙입니다.
긴 리뷰에서 shape가 너무 큼 truncation을 하지 않음 padding보다 먼저 `ids[:max_length]`를 적용합니다.
`RuntimeError`가 embedding에서 발생 token id tensor dtype이 float `dtype=torch.long`으로 만듭니다.
완료 체크

GPTForSequenceClassification

역할: GPT hidden state -> 감성 logits 입력: `(B,T)` 출력: `(B,num_labels)`

GPT는 원래 모든 위치에서 다음 token logits `(B,T,V)`를 만드는 모델입니다. 감성 분류에서는 vocab 전체를 예측하지 않습니다. 리뷰 전체를 대표하는 hidden vector 하나를 뽑고, 그 벡터를 `num_labels`개의 class 점수로 바꿉니다.

input_ids (B,T)
->
embedding
->
blocks x N
->
final_norm
->
last hidden (B,C)
->
Linear(C,2)
->
logits (B,2)

`C`는 `gpt_model.config["emb_dim"]`입니다. tests의 tiny config에서는 `C=16`이므로 classifier는 `Linear(16,2)`가 됩니다.

GPT hidden state를 직접 꺼내야 하는 이유

현재 프로젝트의 `GPTModel.forward(input_ids)`는 최종 LM head까지 지난 logits를 반환합니다. 그러나 분류 head에는 LM logits `(B,T,V)`가 아니라 Transformer의 hidden state `(B,T,C)`가 필요합니다. 따라서 분류 wrapper 안에서는 `self.gpt(input_ids)`를 바로 부르기보다 GPT의 내부 구성 요소를 순서대로 재사용합니다. 

x = self.gpt.embedding(input_ids)       # (B,T,C)
for block in self.gpt.blocks:
    x = block(x)                        # (B,T,C)
x = self.gpt.final_norm(x)              # (B,T,C)
`self.gpt.blocks`가 `nn.ModuleList`라면 `self.gpt.blocks(x)`처럼 직접 호출할 수 없습니다. 반드시 `for block in self.gpt.blocks`로 순회하세요.

문장 대표 벡터: 왜 마지막 token인가?

GPT는 causal self-attention을 쓰기 때문에 마지막 위치의 hidden state는 앞의 token들을 모두 볼 수 있습니다. 그래서 `x[:, -1, :]`를 리뷰 전체의 대표 벡터처럼 사용할 수 있습니다. padding이 많은 실제 학습에서는 마지막 non-pad 위치를 쓰는 방식도 가능하지만, 이 과제의 테스트와 단순 구현에서는 마지막 위치 pooling이 충분합니다.

프로젝트 버전 참고 코드: GPTForSequenceClassification 
class GPTForSequenceClassification(nn.Module):
    def __init__(
        self,
        gpt_model: GPTModel,
        num_labels: int = 2,
        drop_rate: float = 0.1,
    ):
        super().__init__()
        self.gpt = gpt_model
        self.num_labels = num_labels
        emb_dim = gpt_model.config["emb_dim"]
        self.dropout = nn.Dropout(drop_rate)
        self.classifier = nn.Linear(emb_dim, num_labels)

    def forward(
        self,
        input_ids: torch.Tensor,
        labels: torch.Tensor | None = None,
    ) -> torch.Tensor | tuple[torch.Tensor, torch.Tensor]:
        x = self.gpt.embedding(input_ids)
        for block in self.gpt.blocks:
            x = block(x)
        x = self.gpt.final_norm(x)

        pooled = x[:, -1, :]
        logits = self.classifier(self.dropout(pooled))

        if labels is None:
            return logits

        labels = labels.to(input_ids.device).long()
        loss = torch.nn.functional.cross_entropy(logits, labels)
        return loss, logits

PyTorch 함수 명세

코드 shape 계약 의미
nn.Dropout(drop_rate) `(B,C)` -> `(B,C)` 분류 head 앞에서 과적합을 줄입니다.
nn.Linear(emb_dim, num_labels) `(B,C)` -> `(B,num_labels)` hidden vector를 class별 score로 바꿉니다.
x[:, -1, :] `(B,T,C)` -> `(B,C)` 각 batch 샘플의 마지막 위치 hidden state를 고릅니다.
cross_entropy(logits, labels) `(B,2)` + `(B,)` -> scalar softmax와 negative log likelihood가 내부에서 함께 계산됩니다.

흔한 에러와 원인

증상 원인 해결
출력이 `(B,T,V)`로 나옴 `self.gpt(input_ids)`를 그대로 반환 LM head 전 hidden state를 직접 만들고 classifier를 통과시킵니다.
`mat1 and mat2 shapes cannot be multiplied` Linear 입력 차원이 `emb_dim`과 다름 `pooled.shape == (B, emb_dim)`인지 출력해 확인합니다.
`TypeError` 또는 `NotImplementedError` `__init__` 끝의 placeholder를 남김 `raise NotImplementedError`를 제거하고 submodule을 정의합니다.
완료 체크

train_epoch_sentiment / evaluate_sentiment

훈련과 평가는 거의 같은 batch loop를 돌지만, gradient와 model mode가 다릅니다. 훈련은 parameter를 업데이트하고, 평가는 현재 parameter로 loss/accuracy만 측정합니다.

batch
->
to(device)
->
model
->
loss/logits
->
accuracy
->
mean loss, acc

batch shape: `input_ids (B,T)`, `labels (B)`, `logits (B,2)`, `loss`는 scalar입니다.

훈련 함수 구현 순서

  1. `model.train()`으로 dropout과 gradient가 훈련 모드로 동작하게 합니다.
  2. 누적 변수 `total_loss`, `total_correct`, `total_count`를 0으로 둡니다.
  3. 각 batch에서 `input_ids`, `labels`를 device로 옮깁니다.
  4. `optimizer.zero_grad()`로 이전 gradient를 지웁니다.
  5. `loss, logits = model(input_ids, labels=labels)`를 호출합니다.
  6. `loss.backward()`로 gradient를 계산합니다.
  7. `optimizer.step()`으로 parameter를 업데이트합니다.
  8. `loss.item() * batch_size`와 맞은 개수를 누적합니다.
  9. 마지막에 평균 loss와 accuracy를 반환합니다.
프로젝트 버전 참고 코드: train_epoch_sentiment 
def train_epoch_sentiment(
    model: GPTForSequenceClassification,
    train_loader,
    optimizer: torch.optim.Optimizer,
    device: torch.device,
) -> tuple[float, float]:
    model.train()
    total_loss = 0.0
    total_correct = 0
    total_count = 0

    for input_ids, labels in train_loader:
        input_ids = input_ids.to(device)
        labels = labels.to(device).long()

        optimizer.zero_grad()
        loss, logits = model(input_ids, labels=labels)
        loss.backward()
        optimizer.step()

        batch_size = labels.size(0)
        total_loss += loss.item() * batch_size
        preds = logits.argmax(dim=-1)
        total_correct += (preds == labels).sum().item()
        total_count += batch_size

    if total_count == 0:
        return 0.0, 0.0
    return total_loss / total_count, total_correct / total_count

평가 함수 구현 순서

  1. `model.eval()`로 dropout을 끕니다.
  2. `with torch.no_grad():` 안에서 batch loop를 돕니다.
  3. 훈련과 똑같이 loss, logits, accuracy를 계산하지만 backward와 optimizer step은 하지 않습니다.
  4. 마지막에 평균 loss와 accuracy를 반환합니다.
프로젝트 버전 참고 코드: evaluate_sentiment 
def evaluate_sentiment(
    model: GPTForSequenceClassification,
    data_loader,
    device: torch.device,
) -> tuple[float, float]:
    model.eval()
    total_loss = 0.0
    total_correct = 0
    total_count = 0

    with torch.no_grad():
        for input_ids, labels in data_loader:
            input_ids = input_ids.to(device)
            labels = labels.to(device).long()

            loss, logits = model(input_ids, labels=labels)

            batch_size = labels.size(0)
            total_loss += loss.item() * batch_size
            preds = logits.argmax(dim=-1)
            total_correct += (preds == labels).sum().item()
            total_count += batch_size

    if total_count == 0:
        return 0.0, 0.0
    return total_loss / total_count, total_correct / total_count

흔한 에러와 원인

증상 원인 해결
loss 평균이 batch size에 따라 이상하게 흔들림 batch별 loss를 단순 평균하고 마지막 작은 batch를 고려하지 않음 `loss.item() * batch_size`를 누적하고 전체 샘플 수로 나눕니다.
GPU 사용 시 device mismatch labels만 CPU에 남아 있음 `input_ids`와 `labels` 둘 다 `.to(device)` 합니다.
평가가 느리고 메모리가 늘어남 `torch.no_grad()` 누락 eval loop 전체를 `with torch.no_grad():`로 감쌉니다.
accuracy가 tensor로 남아 출력이 이상함 `.item()` 없이 tensor를 누적 `(preds == labels).sum().item()`으로 Python 숫자로 바꿉니다.
