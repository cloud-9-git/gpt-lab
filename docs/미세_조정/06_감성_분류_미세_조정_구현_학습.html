06_감성 분류 미세 조정 구현 학습

교재 ch06의 분류 미세 튜닝 흐름을 NSMC 영화 리뷰 감성 분류 과제에 맞춰 바꿔 봅니다. 핵심은 GPT가 다음 토큰을 맞히던 모델에서 리뷰 하나의 긍정/부정 label을 맞히는 모델로 바뀐다는 점입니다.

무엇을 만드는가 사전 학습과 차이 데이터셋 분류 모델 훈련과 평가 구현 순서

무엇을 만드는가

이번 과제의 구현 파일은 src/finetune.py입니다. 목표는 영화 리뷰 텍스트 하나를 받아 0 또는 1 감성 label을 예측하는 분류 모델과 그 모델을 훈련/평가하는 유틸리티를 만드는 것입니다.

구현 대상 역할 테스트가 보는 핵심
make_sentiment_dataset NSMC TSV를 읽어 train/validation/test 데이터를 만듭니다. 빈 리뷰 제거, {"text", "label"} 형식, split 개수
ReviewSentimentDataset 리뷰를 token ID로 바꾸고 max_length에 맞춰 padding/truncation합니다. (max_length,) LongTensor와 label 반환
GPTForSequenceClassification GPT backbone 위에 감성 분류용 classifier head를 붙입니다. logits shape가 (B, num_labels)
train_epoch_sentiment, evaluate_sentiment 분류 loss와 accuracy로 훈련/평가합니다. 호출 가능한 함수, 평균 loss와 accuracy 반환
교재 ch06은 스팸/스팸 아님 분류를 예제로 씁니다. 우리 과제는 같은 구조를 NSMC 영화 리뷰의 부정/긍정 분류로 바꾸는 것입니다.

사전 학습과 감성 분류의 차이

사전 학습에서는 입력 문장의 모든 위치마다 다음 토큰을 맞힙니다. 그래서 모델 출력은 보통 (B, T, vocab_size)이고 target도 (B, T)입니다.

감성 분류에서는 리뷰 하나마다 label 하나만 맞히면 됩니다. 그래서 최종 출력은 (B, num_labels)이고 target은 (B,)입니다.

사전 학습 input_ids: (B, T) GPT logits: (B, T, vocab_size) targets: (B, T) loss: 모든 위치의 다음 토큰 예측 감성 분류 미세 조정 input_ids: (B, T) GPT hidden: (B, T, emb_dim) last hidden: (B, emb_dim) classifier logits: (B, 2) labels: (B,) loss: 리뷰 하나의 감성 label 예측

왜 마지막 token을 보는가

GPT는 causal mask를 사용합니다. 앞쪽 토큰은 뒤쪽 토큰을 볼 수 없지만, 마지막 위치의 hidden state는 자기 앞의 모든 토큰을 볼 수 있습니다. 그래서 교재 ch06 흐름처럼 마지막 token 위치의 표현을 문장 대표 벡터로 사용합니다.

리뷰: "이 영화는 정말 좋았다" 위치 0: "이" -> "이"만 참고 위치 1: "영화는" -> "이", "영화는" 참고 위치 2: "정말" -> "이", "영화는", "정말" 참고 위치 3: "좋았다" -> 앞의 모든 token 참고 분류에서는 마지막 위치의 hidden state를 classifier에 넣는다.

NSMC 데이터셋 만들기

NSMC 파일은 보통 id, document, label 열을 가진 TSV입니다. document가 리뷰 본문이고, label은 감성 label입니다.

make_sentiment_dataset

이 함수는 TSV를 읽어서 Python list 형태의 데이터를 반환하면 됩니다. 

[
    {"text": "정말 좋았다", "label": 1},
    {"text": "별로였다", "label": 0},
]

구현 흐름은 다음 순서로 생각하면 됩니다.

  1. train_tsv_path를 읽습니다.
  2. 헤더 id document label는 데이터가 아니므로 건너뜁니다.
  3. document가 비어 있는 행은 제거합니다.
  4. label은 문자열이 아니라 정수 0 또는 1로 바꿉니다.
  5. seed를 고정해서 train 데이터를 섞은 뒤 val_ratio만큼 validation으로 나눕니다.
  6. test_tsv_path가 있으면 같은 방식으로 test 데이터를 만듭니다.
테스트에서는 빈 리뷰가 하나 들어 있습니다. 그 행까지 데이터로 넣으면 split 개수가 맞지 않습니다.

ReviewSentimentDataset

이 클래스는 DataLoader가 바로 배치를 만들 수 있도록 리뷰 길이를 모두 같은 길이로 맞춰야 합니다. 길면 자르고, 짧으면 padding token ID를 뒤에 붙입니다. 

ids = tokenizer.encode(text, add_bos_eos=True)
ids = ids[:max_length]
ids = ids + [pad_id] * (max_length - len(ids))
input_ids = torch.tensor(ids, dtype=torch.long)
상황 처리
토큰 길이가 max_length보다 김 ids[:max_length]로 자릅니다.
토큰 길이가 max_length보다 짧음 pad_id를 뒤에 붙여 길이를 맞춥니다.
label 분류 손실에서 쓸 수 있게 정수 label로 반환합니다.

GPT 위에 분류 Head 붙이기

기존 GPTModel의 lm_head는 다음 토큰 예측용입니다. 즉 emb_dim을 vocab_size로 바꿉니다. 감성 분류에서는 어휘사전 전체가 아니라 긍정/부정 두 클래스만 맞히면 되므로 별도의 classifier가 필요합니다.

GPT hidden state (B, T, emb_dim) | | 마지막 위치 선택: x[:, -1, :] v 문장 대표 벡터 (B, emb_dim) | | Dropout | Linear(emb_dim, num_labels) v 감성 logits (B, 2)

왜 GPTModel.forward를 그대로 쓰면 부족한가

현재 GPTModel.forward는 hidden state를 lm_head까지 통과시켜 (B, T, vocab_size) logits를 반환합니다. 하지만 분류 head는 lm_head 이전의 hidden state, 즉 (B, T, emb_dim)이 필요합니다.

그래서 GPTForSequenceClassification.forward 안에서는 GPT의 내부 구성요소를 재사용해 hidden state까지만 계산하고, 마지막 위치를 뽑아 classifier에 넣는 방식으로 구현하면 됩니다. 

x = self.gpt.embedding(input_ids)

for block in self.gpt.blocks:
    x = block(x)

x = self.gpt.final_norm(x)
last_hidden = x[:, -1, :]
logits = self.classifier(self.dropout(last_hidden))

labels가 없으면 logits만 반환하고, labels가 있으면 cross_entropy로 loss를 계산해 (loss, logits)를 반환합니다. 

if labels is None:
    return logits

loss = torch.nn.functional.cross_entropy(logits, labels)
return loss, logits
cross_entropy에는 softmax를 직접 넣지 않습니다. PyTorch의 cross entropy가 내부에서 logits를 확률처럼 다룰 준비를 해 줍니다.

훈련과 평가

사전 학습 훈련 루프와 구조는 거의 같습니다. 다른 점은 target이 다음 token ID가 아니라 감성 label이라는 점, 그리고 평가할 때 generated text가 아니라 accuracy를 본다는 점입니다.

train_epoch_sentiment

  1. model.train()으로 훈련 모드를 켭니다.
  2. DataLoader에서 input_ids, labels를 꺼냅니다.
  3. 둘 다 device로 보냅니다.
  4. loss, logits = model(input_ids, labels=labels)로 손실을 얻습니다.
  5. optimizer.zero_grad(), loss.backward(), optimizer.step() 순서로 업데이트합니다.
  6. argmax로 예측 label을 구하고 accuracy를 누적합니다.
preds = torch.argmax(logits, dim=-1)
correct += (preds == labels).sum().item()
total += labels.numel()

evaluate_sentiment

평가는 모델을 업데이트하지 않습니다. 그래서 model.eval()과 torch.no_grad()를 같이 씁니다. 

model.eval()

with torch.no_grad():
    loss, logits = model(input_ids, labels=labels)
반환값은 둘 다 (평균 loss, accuracy) 형태가 좋습니다. accuracy는 0.0부터 1.0 사이 비율로 계산하면 됩니다.

구현 순서

  1. make_sentiment_dataset에서 TSV 읽기, 빈 리뷰 제거, label 정수 변환, train/val/test split을 구현합니다.
  2. ReviewSentimentDataset.__getitem__에서 encode, truncate, padding, LongTensor 반환을 구현합니다.
  3. GPTForSequenceClassification.__init__에서 Dropout과 Linear(emb_dim, num_labels)를 정의합니다.
  4. GPTForSequenceClassification.forward에서 GPT hidden state를 계산하고 마지막 위치를 classifier에 넣습니다.
  5. train_epoch_sentiment에서 훈련 loss와 accuracy를 누적합니다.
  6. evaluate_sentiment에서 no_grad 평가 loss와 accuracy를 계산합니다.

자주 틀리는 지점

  • lm_head의 vocab_size 출력으로 분류하려고 하면 shape가 맞지 않습니다.
  • labels는 one-hot이 아니라 (B,) 모양의 정수 class ID여야 합니다.
  • input_ids dtype은 torch.long이어야 embedding에 들어갈 수 있습니다.
  • evaluate_sentiment에서 no_grad를 빼면 불필요하게 그래프를 저장합니다.
  • 리뷰가 비어 있는 TSV 행을 제거하지 않으면 테스트 split 개수가 어긋납니다.
