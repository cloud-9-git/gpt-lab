05_사전 학습 구현 학습

GPT 모델을 실제로 학습시키기 위해 loss 계산, 평가, 샘플 생성, checkpoint 저장과 복원을 어떻게 연결하는지 차근차근 정리합니다.

목표 전체 흐름 Loss 평가 생성 저장/복원 Token Cache 구현 순서 테스트

1. 이 과제에서 만드는 것

src/train.py는 GPT 모델 자체가 아니라, 모델을 훈련하고 평가하고 저장하기 위한 도구들을 담습니다. 교재 ch05에서는 이 단계에서 텍스트 생성 모델의 loss를 계산하고, 모델을 학습시키고, 생성 방식을 다양화하고, 나중에 이어서 학습할 수 있도록 상태를 저장합니다.

함수 하는 일 왜 필요한가
calc_loss_batch 한 batch의 다음 토큰 예측 loss 계산 학습에서 줄여야 할 값을 만든다
calc_loss_loader 여러 batch의 평균 loss 계산 train/validation 성능을 비교한다
save_checkpoint 모델, optimizer, epoch, step 저장 학습을 중단한 지점에서 이어갈 수 있다
load_checkpoint 저장한 checkpoint 복원 같은 학습 상태를 다시 만든다
generate temperature/top-k 생성 항상 같은 토큰만 고르지 않게 조절한다
train_model 전체 사전 학습 루프 loss 계산, 역전파, 평가, 샘플 출력을 묶는다

2. 사전 학습 전체 흐름

GPT 사전 학습은 레이블이 따로 있는 분류 문제가 아닙니다. 입력 토큰을 한 칸 민 target을 정답으로 삼아 “다음 토큰 맞히기”를 반복합니다.

token ids input: [A, B, C, D] target: [B, C, D, E] model(input) -> logits: 각 위치마다 vocab 전체에 대한 점수 loss(logits, target) -> 정답 다음 토큰의 점수가 높아지도록 학습

한 epoch 안에서는 DataLoader가 여러 batch를 내보내고, 모델은 각 batch마다 loss를 계산합니다. loss.backward()는 gradient를 만들고, optimizer.step()은 그 gradient를 사용해 파라미터를 갱신합니다.

for epoch: for input_batch, target_batch in train_loader: loss 계산 gradient 계산 optimizer로 weight 업데이트 validation loss 확인 샘플 텍스트 생성

3. Loss 계산 이해하기

3.1 logits와 targets shape

모델 출력인 logits는 (B, T, V)입니다. 여기서 B는 batch size, T는 토큰 길이, V는 vocabulary size입니다.

input_batch: (B, T) target_batch: (B, T) logits: (B, T, V)

torch.nn.functional.cross_entropy는 보통 (N, C) 형태의 예측과 (N) 형태의 정답을 받습니다. 그래서 앞의 두 차원 B와 T를 하나로 합칩니다.

logits: (B, T, V) -> (B*T, V) targets: (B, T) -> (B*T)

3.2 한 batch loss

calc_loss_batch는 batch를 device로 옮긴 뒤, 모델을 호출하고, logits와 target을 펼쳐 loss를 계산합니다. 

input_batch = input_batch.to(device)
target_batch = target_batch.to(device)

logits = model(input_batch)
loss = torch.nn.functional.cross_entropy(
    logits.flatten(0, 1),
    target_batch.flatten(),
)
cross_entropy에는 softmax를 적용한 확률이 아니라 raw logits를 넣습니다. PyTorch가 내부에서 softmax에 해당하는 계산까지 처리합니다.

4. Train Loss와 Validation Loss

train loss는 모델이 학습한 데이터에서 얼마나 잘 맞히는지 보여 줍니다. validation loss는 학습에 직접 사용하지 않은 데이터에서 얼마나 잘 맞히는지 보여 줍니다. 둘을 같이 봐야 모델이 일반화하는지, 아니면 훈련 데이터를 외우는지 알 수 있습니다.

train loss 내려감 validation loss 같이 내려감 -> 학습이 잘 진행되는 중 train loss 계속 내려감 validation loss 멈추거나 올라감 -> 과대적합 가능성

4.1 loader 평균 loss

calc_loss_loader는 DataLoader에서 batch를 여러 개 꺼내고, 각 batch의 loss를 더한 뒤 평균을 냅니다. num_batches가 주어지면 전체 loader가 아니라 일부 batch만 평가할 수 있습니다.

total_loss = 0 for batch in data_loader: batch_loss = calc_loss_batch(...) total_loss += batch_loss avg_loss = total_loss / batch_count

4.2 eval 모드와 no_grad

평가할 때는 weight를 업데이트하지 않습니다. 그래서 torch.no_grad()로 gradient 기록을 끄고, model.eval()로 dropout 같은 훈련 전용 동작을 끕니다. 

model.eval()
with torch.no_grad():
    train_loss = calc_loss_loader(train_loader, model, device, num_batches=eval_iter)
    val_loss = calc_loss_loader(val_loader, model, device, num_batches=eval_iter)
model.train()

5. 생성 전략 이해하기

generate_text_simple은 마지막 위치의 logits에서 가장 큰 값을 고르는 greedy decoding입니다. 이번 과제의 generate는 여기에 temperature와 top-k sampling을 추가합니다.

5.1 마지막 위치 logits만 보는 이유

idx = [A, B, C, D] logits[:, 0, :] -> A 다음 예측 logits[:, 1, :] -> A B 다음 예측 logits[:, 2, :] -> A B C 다음 예측 logits[:, 3, :] -> A B C D 다음 예측 생성에서 필요한 것: A B C D 다음에 붙일 토큰 따라서: logits = logits[:, -1, :]

5.2 temperature

temperature는 logits를 나누는 값입니다. 낮은 temperature는 확률분포를 뾰족하게 만들어 가장 유력한 토큰을 더 자주 고르게 합니다. 높은 temperature는 분포를 더 평평하게 만들어 다양한 토큰이 나올 가능성을 키웁니다.

설정 동작
temperature <= 0 argmax로 가장 큰 logit 선택
temperature = 1 logits를 그대로 softmax 후 샘플링
temperature > 1 더 다양한 토큰이 선택될 가능성 증가

5.3 top-k

top-k는 가장 점수가 높은 k개 토큰만 후보로 남기고 나머지는 -inf로 바꿉니다. softmax 뒤에는 -inf였던 위치의 확률이 0이 됩니다.

logits [4.5, 0.8, -1.9, 6.7, 1.6, 6.2] top_k = 3 [4.5, -inf, -inf, 6.7, -inf, 6.2] softmax [확률 있음, 0, 0, 확률 있음, 0, 확률 있음]

6. Checkpoint 이해하기

모델을 저장할 때는 model.state_dict()만 저장할 수도 있습니다. 하지만 훈련을 이어가려면 optimizer 상태, 현재 epoch, global step도 같이 저장하는 편이 안전합니다.

저장할 것 model_state_dict optimizer_state_dict epoch global_step

load_checkpoint는 저장된 dict를 읽고, 모델에는 model state를 넣고, optimizer가 주어진 경우에는 optimizer state도 복원합니다. 마지막으로 epoch와 global step을 반환합니다.

테스트에서는 저장한 checkpoint를 새 모델과 새 optimizer에 로드한 뒤 epoch와 step이 그대로 돌아오는지 확인합니다.

7. Token ID 캐시

사전 학습을 Colab에서 반복 실행할 때 corpus를 매번 tokenizer.encode()하면 준비 시간이 낭비됩니다. 한 번 token ID 리스트로 바꾼 뒤 파일로 저장해두면, 다음 실행부터는 저장된 ID를 바로 읽어서 DataLoader를 만들 수 있습니다.

첫 실행 corpus text -> tokenizer.encode(corpus) -> token_ids 저장 -> DataLoader 생성 다음 실행 저장된 token_ids 로드 -> DataLoader 생성
from train import get_or_create_token_ids
from dataset import create_dataloader

token_ids = get_or_create_token_ids(
    corpus=train_text,
    tokenizer=tokenizer,
    cache_path="data/train_token_ids.pt",
)

train_loader = create_dataloader(
    token_ids,
    context_length=config["context_length"],
    batch_size=16,
    stride=config["context_length"],
)
토크나이저의 vocab/merge rule 저장은 “토크나이저 학습”을 건너뛰게 해주고, token_ids 저장은 “긴 텍스트 encode”를 건너뛰게 해줍니다. 학습 준비 시간을 줄이는 데 직접적인 것은 token_ids 캐시입니다.

8. 추천 구현 순서

  1. calc_loss_batch를 먼저 구현하고 scalar loss가 나오는지 확인합니다.
  2. calc_loss_loader를 구현해서 여러 batch 평균을 계산합니다.
  3. save_checkpoint, load_checkpoint를 구현합니다.
  4. generate를 greedy 방식으로 먼저 만들고, top-k와 temperature를 추가합니다.
  5. generate_and_print_sample에서 encode, generate, decode 흐름을 연결합니다.
  6. train_model에서 학습 루프, 평가, 샘플 출력, checkpoint 저장을 연결합니다.

train_model의 기본 뼈대

train_losses = []

for epoch in range(start_epoch, start_epoch + num_epochs):
    model.train()

    for input_batch, target_batch in train_loader:
        optimizer.zero_grad()
        loss = calc_loss_batch(input_batch, target_batch, model, device)
        loss.backward()
        optimizer.step()
        global_step += 1

        if global_step % eval_freq == 0:
            model.eval()
            with torch.no_grad():
                train_loss = calc_loss_loader(train_loader, model, device, eval_iter)
                val_loss = calc_loss_loader(val_loader, model, device, eval_iter)
            model.train()

    train_losses.append(train_loss)
    generate_and_print_sample(...)

return train_losses

10. 자주 막히는 곳

1. logits를 펼치지 않고 loss에 넣음

cross_entropy에 넣기 전에 (B, T, V)를 (B*T, V)로, target의 (B, T)를 (B*T)로 바꿔야 합니다.

2. 평가 중에도 gradient를 기록함

validation loss 계산에는 torch.no_grad()를 사용하세요. 학습하지 않는데 기록을 남기면 메모리와 시간이 낭비됩니다.

3. top-k의 기준값 shape가 맞지 않음

batch마다 top-k 기준값이 다르므로 top_logits[:, -1]만 쓰지 말고, 비교가 잘 broadcast되도록 unsqueeze(-1)를 붙이는 편이 안전합니다.

4. optimizer state를 저장하지 않음

모델 weight만 복원하면 추론은 가능하지만, 학습을 이어갈 때 optimizer의 내부 상태가 사라집니다.

5. model.train()으로 되돌리지 않음

평가나 샘플 생성 후에는 다시 학습 모드로 돌려야 dropout 같은 훈련 동작이 정상적으로 적용됩니다.
