2. 레이블 없는 데이터를 위한 사전 훈련 흐름

사전 훈련 데이터에는 정답 label이 따로 없습니다. 대신 문장 자체를 한 칸 밀어서 target으로 만듭니다. GPT는 현재 token들을 보고 다음 token을 맞히는 방식으로 학습합니다.

raw text
->
token ids
->
input / target
shift
->
GPTModel
->
cross entropy
->
optimizer step

핵심 shape: input과 target은 둘 다 (B, T)이고, 모델 logits는 (B, T, V)입니다.

input/target shift

token_ids = [10, 11, 12, 13, 14]
input  = [10, 11, 12, 13]
target = [11, 12, 13, 14]

이 구조 덕분에 label 파일이 없어도 “다음 token ID”가 정답이 됩니다. 그래서 `train.py`의 loss 함수는 sentiment label이 아니라 token ID target을 사용합니다.

loss flatten 흐름

logits
(B, T, V)
->
view(-1, V)
=
(B*T, V)
targets
(B, T)
->
view(-1)
=
(B*T)

이 과제의 GPTModel.forward(idx, targets)가 이미 이 flatten과 cross entropy를 처리하도록 구현되어야 합니다. 그래서 train.py에서는 모델을 targets와 함께 호출해 loss를 받으면 됩니다.

4. calc_loss_batch

한 batch의 input/target을 device로 옮긴 뒤 모델을 호출해서 scalar loss를 얻는 함수입니다.

역할 한 줄 요약

한 batch에 대한 다음 token 예측 loss를 계산합니다.

입력/출력 shape

input_batch: (B, T), target_batch: (B, T) -> scalar loss

필요한 PyTorch API

  • Tensor.to
  • model(..., targets=...)

구현 순서

  1. input_batch와 target_batch를 같은 device로 옮깁니다.
  2. model(input_batch, targets=target_batch)를 호출합니다.
  3. 반환된 (loss, logits) 중 loss만 반환합니다.
프로젝트 버전 참고 코드: calc_loss_batch 
def calc_loss_batch(input_batch, target_batch, model, device):
    input_batch = input_batch.to(device)
    target_batch = target_batch.to(device)
    loss, _ = model(input_batch, targets=target_batch)
    return loss

흔한 에러

input만 device로 이동 target이 CPU에 남으면 GPU 학습에서 device mismatch가 납니다.
logits를 반환 테스트는 scalar loss를 기대합니다. 반환값은 loss여야 합니다. 
pytest tests/test_train.py::TestCalcLossBatch::test_calc_loss_batch_returns_scalar -v
완료 체크: 반환 tensor의 dim()이 0이고 값이 0 이상이면 다음으로 이동합니다.

5. calc_loss_loader

data loader 여러 batch의 평균 loss를 계산합니다. 검증용 함수이므로 gradient 기록을 끄고 평가 모드로 계산합니다.

model.eval()
->
torch.no_grad()
->
batch loss 누적
->
평균 loss

평가 중에는 dropout이 꺼지고 gradient graph를 만들지 않으므로 더 안정적이고 가볍게 loss를 볼 수 있습니다.

역할 한 줄 요약

loader에서 일부 또는 전체 batch의 평균 loss를 계산합니다.

입력/출력

data_loader -> float 또는 scalar tensor

필요한 PyTorch API

  • model.eval
  • torch.no_grad
  • enumerate
  • Tensor.item

구현 순서

  1. loader가 비어 있으면 float("nan") 또는 0.0처럼 안전한 값을 반환합니다.
  2. num_batches가 있으면 그 개수까지만 계산합니다.
  3. model.eval() 뒤 torch.no_grad() 안에서 batch loss를 누적합니다.
  4. 계산한 batch 수로 나눈 평균을 반환합니다.
  5. 이 함수가 끝난 뒤 학습 루프에서는 다시 model.train()을 호출해야 합니다.
프로젝트 버전 참고 코드: calc_loss_loader 
def calc_loss_loader(data_loader, model, device, num_batches=None):
    if len(data_loader) == 0:
        return float("nan")

    if num_batches is None:
        num_batches = len(data_loader)
    else:
        num_batches = min(num_batches, len(data_loader))

    total_loss = 0.0
    model.eval()
    with torch.no_grad():
        for batch_idx, (input_batch, target_batch) in enumerate(data_loader):
            if batch_idx >= num_batches:
                break
            loss = calc_loss_batch(input_batch, target_batch, model, device)
            total_loss += loss.item()

    return total_loss / num_batches

흔한 에러

torch.no_grad() 누락 검증 중에도 gradient graph가 쌓여 메모리를 낭비합니다.
num_batches 무시 테스트는 num_batches=2 같은 제한 동작을 기대합니다.
0으로 나누기 빈 loader나 num_batches=0 상황을 안전하게 처리해야 합니다. 
pytest tests/test_train.py::TestCalcLossLoader::test_calc_loss_loader_returns_float -v
완료 체크: 평균 loss가 float 또는 scalar tensor이고 0 이상이면 다음으로 이동합니다.

6. checkpoint 저장과 로드

checkpoint는 “모델 가중치만”이 아니라 “학습을 이어가기 위한 상태”입니다. optimizer state, epoch, global step을 같이 저장해야 같은 지점에서 재개할 수 있습니다.

model state
optimizer state
epoch
global_step
->
torch.save
->

역할 한 줄 요약

저장 함수는 학습 상태를 파일로 쓰고, 로드 함수는 모델/옵티마이저와 epoch/step을 복원합니다.

입력/출력

save_checkpoint는 반환 없음, load_checkpoint는 (epoch, global_step) 반환

필요한 PyTorch API

  • torch.save
  • torch.load
  • model.state_dict
  • model.load_state_dict
  • optimizer.state_dict
  • optimizer.load_state_dict
프로젝트 버전 참고 코드: checkpoint 
def save_checkpoint(model, optimizer, epoch, global_step, path):
    checkpoint = {
        "model_state_dict": model.state_dict(),
        "optimizer_state_dict": optimizer.state_dict(),
        "epoch": epoch,
        "global_step": global_step,
    }
    torch.save(checkpoint, path)

def load_checkpoint(model, optimizer, path, device):
    checkpoint = torch.load(path, map_location=device)
    model.load_state_dict(checkpoint["model_state_dict"])
    if optimizer is not None and "optimizer_state_dict" in checkpoint:
        optimizer.load_state_dict(checkpoint["optimizer_state_dict"])
    return checkpoint.get("epoch", 0), checkpoint.get("global_step", 0)

흔한 에러

optimizer state 미저장 테스트는 epoch/step만 보지만 실제 재개 학습에서는 optimizer 상태도 중요합니다.
map_location 누락 GPU에서 저장한 파일을 CPU에서 읽을 때 문제가 날 수 있습니다.
optimizer=None 미처리 평가 전용 로드에서는 optimizer 없이도 모델만 복원할 수 있어야 합니다. 
pytest tests/test_train.py::TestCheckpoint::test_save_load_checkpoint_restores_epoch_and_step -v
완료 체크: 저장 후 새 모델/옵티마이저에 로드했을 때 epoch와 global_step이 그대로 돌아옵니다.

7. generate: temperature와 top-k

model.py의 simple generation이 greedy라면, 이 함수는 무작위성을 조절하는 sampling generation입니다. temperature로 분포의 날카로움을 조절하고, top-k로 후보 token을 제한합니다.

idx
(B, cur_len)
->
idx_cond
(B, <= context_size)
->
model
->
last logits
(B, V)
->
sample
(B, 1)

temperature/top-k 흐름

logits
->
top-k 외부
-inf
->
divide by
temperature
->
softmax
->
multinomial

낮은 temperature는 더 결정적이고, 높은 temperature는 더 다양한 token을 뽑게 만듭니다. top-k는 확률이 낮은 token을 후보에서 제외합니다.

역할 한 줄 요약

다음 token을 greedy가 아니라 확률적으로 뽑아 더 다양한 텍스트를 생성합니다.

입력/출력 shape

idx: (B, start_len) -> out: (B, start_len + max_new_tokens)

필요한 PyTorch API

  • torch.no_grad
  • torch.topk
  • torch.softmax
  • torch.multinomial
  • torch.cat
프로젝트 버전 참고 코드: generate 
def generate(model, idx, max_new_tokens, context_size, temperature=1.0, top_k=None, eos_id=None):
    for _ in range(max_new_tokens):
        idx_cond = idx[:, -context_size:]
        with torch.no_grad():
            logits = model(idx_cond)
        logits = logits[:, -1, :]

        if top_k is not None:
            top_values, _ = torch.topk(logits, top_k)
            min_value = top_values[:, -1].unsqueeze(-1)
            logits = torch.where(
                logits < min_value,
                torch.full_like(logits, -torch.inf),
                logits,
            )

        if temperature <= 0:
            idx_next = torch.argmax(logits, dim=-1, keepdim=True)
        else:
            logits = logits / temperature
            probs = torch.softmax(logits, dim=-1)
            idx_next = torch.multinomial(probs, num_samples=1)

        idx = torch.cat((idx, idx_next), dim=1)
        if eos_id is not None and torch.all(idx_next == eos_id):
            break
    return idx

흔한 에러

마지막 위치만 고르지 않음 logits[:, -1, :]가 다음 token 후보입니다.
top_k가 vocab보다 큼 안전하게 구현하려면 top_k = min(top_k, logits.size(-1))로 제한할 수 있습니다.
temperature 0에서 나누기 0 이하일 때는 sampling 대신 argmax로 처리하면 안전합니다.
idx_next가 (B) concat을 위해 (B, 1)이어야 합니다. 
pytest tests/test_train.py::TestGenerate::test_generate_shape -v
완료 체크: top-k와 temperature를 넣어도 결과 길이가 start_len + max_new_tokens가 됩니다.

8. generate_and_print_sample

학습 중 사람이 볼 샘플을 출력하는 helper입니다. tokenizer로 시작 문장을 encode하고, generate 결과를 다시 decode해서 출력합니다.

역할 한 줄 요약

학습 중 모델이 어떤 문장을 생성하는지 빠르게 눈으로 확인합니다.

주의점

출력용 함수라 테스트가 직접 보지는 않지만, train_model에서 호출하면 학습 상태 확인에 유용합니다.

필요한 API

  • tokenizer.encode
  • tokenizer.decode
  • torch.tensor
  • model.eval
  • model.train
프로젝트 버전 참고 코드: generate_and_print_sample 
def generate_and_print_sample(
    model,
    tokenizer,
    device,
    start_context,
    max_new_tokens=50,
    context_size=256,
    temperature=0.8,
    top_k=40,
):
    model.eval()
    encoded = tokenizer.encode(start_context)
    idx = torch.tensor(encoded, dtype=torch.long, device=device).unsqueeze(0)
    eos_id = tokenizer.get_eos_id() if hasattr(tokenizer, "get_eos_id") else None
    token_ids = generate(
        model,
        idx,
        max_new_tokens=max_new_tokens,
        context_size=context_size,
        temperature=temperature,
        top_k=top_k,
        eos_id=eos_id,
    )
    decoded = tokenizer.decode(token_ids.squeeze(0).tolist())
    print(decoded)
    model.train()

흔한 에러

batch 차원 없음 모델 입력은 (B, T)라서 unsqueeze(0)가 필요합니다.
device 이동 누락 모델이 GPU에 있으면 생성 입력 tensor도 같은 device에 있어야 합니다.
학습 모드 복귀 누락 샘플 출력 후 학습을 계속할 거면 model.train()으로 되돌립니다.

9. train_model

전체 학습 루프입니다. 테스트가 직접 세세히 검증하지 않더라도, 노트북에서 실제 사전 훈련을 하려면 이 함수가 필요합니다.

epoch
->
batch
->
loss
->
backward
->
optimizer step
->
eval/sample/ckpt

핵심 순서

  1. model.to(device)와 model.train()으로 시작합니다.
  2. 각 batch마다 optimizer.zero_grad()를 호출합니다.
  3. calc_loss_batch로 loss를 계산합니다.
  4. loss.backward(), optimizer.step() 순서로 업데이트합니다.
  5. global_step을 증가시킵니다.
  6. eval_freq마다 train/val loss를 계산하고 sample을 출력합니다.
  7. ckpt_freq가 있으면 주기적으로 checkpoint를 저장합니다.
  8. epoch별 평균 train loss 리스트를 반환합니다.
프로젝트 버전 참고 코드: train_model 
def train_model(
    model,
    train_loader,
    val_loader,
    optimizer,
    device,
    num_epochs,
    eval_freq,
    eval_iter,
    start_context,
    tokenizer,
    ckpt_freq=None,
    start_epoch=0,
    global_step=0,
):
    model.to(device)
    train_losses = []

    for epoch in range(start_epoch, start_epoch + num_epochs):
        model.train()
        epoch_loss = 0.0
        num_batches = 0

        for input_batch, target_batch in train_loader:
            optimizer.zero_grad()
            loss = calc_loss_batch(input_batch, target_batch, model, device)
            loss.backward()
            optimizer.step()

            epoch_loss += loss.item()
            num_batches += 1
            global_step += 1

            if eval_freq and global_step % eval_freq == 0:
                train_loss = calc_loss_loader(train_loader, model, device, eval_iter)
                val_loss = calc_loss_loader(val_loader, model, device, eval_iter)
                print(f"step {global_step}: train loss {train_loss:.4f}, val loss {val_loss:.4f}")
                generate_and_print_sample(model, tokenizer, device, start_context)
                model.train()

            if ckpt_freq and global_step % ckpt_freq == 0:
                save_checkpoint(model, optimizer, epoch, global_step, f"checkpoint_step_{global_step}.pt")

        train_losses.append(epoch_loss / max(1, num_batches))

    return train_losses

흔한 에러

zero_grad 누락 이전 batch gradient가 계속 누적됩니다.
backward와 step 순서 바뀜 gradient를 계산한 뒤 optimizer가 parameter를 업데이트해야 합니다.
평가 후 model.train() 누락 dropout이 계속 꺼진 상태로 학습될 수 있습니다.
빈 epoch에서 평균 계산 에러 max(1, num_batches)처럼 0 나누기를 피합니다.
완료 체크: batch마다 loss가 계산되고 optimizer가 step을 수행하며, epoch별 train loss 리스트가 반환됩니다.

TestCalcLossBatch 한 batch loss가 scalar tensor이고 값이 0 이상인지 봅니다.
TestCalcLossLoader loader 평균 loss가 float 또는 scalar tensor로 반환되는지 봅니다.
TestCheckpoint 저장 후 로드했을 때 epoch와 global step이 그대로 복원되는지 봅니다.
TestGenerate temperature/top-k 옵션이 있어도 생성 결과 길이가 요청한 만큼 늘어나는지 봅니다.
TestPlotLosses 제공된 plotting 함수가 예외 없이 호출되는지만 봅니다.

디버깅 표

실패 증상 가능한 원인 먼저 볼 곳
loss가 tuple 또는 logits calc_loss_batch에서 loss만 반환하지 않음 calc_loss_batch
평균 loss 타입 이상 loss.item() 누락 또는 평균 계산 누락 calc_loss_loader
epoch/step 복원 실패 checkpoint dict key가 다르거나 반환값이 없음 checkpoint
생성 shape 불일치 idx_next가 (B, 1)이 아니거나 concat 방향이 틀림 generate
device mismatch batch, idx, model이 같은 device에 있지 않음 batch loss, sample 출력
완료 기준은 tests/test_train.py 전체 통과, scalar loss 반환, checkpoint epoch/step 복원, generation 결과 길이 증가입니다.
